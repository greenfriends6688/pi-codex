## 0. 拆分原则（与既有 PR 计划保持一致，不另立一套）

| 原则 | 说明 |
| --- | --- |
| 单一意图 | 一个 PR 只做一件事。皮肤/CSS 与功能绝不混在一个 PR |
| 可独立回滚 | 每个 PR revert 后系统仍可用；新文件优先于改老文件 |
| ⭐ 不丢上游合并能力 | 新增逻辑放 `lib/`、`components/fork/`、新 api 路由（T0）；碰上游文件打 `fork:<slug>` 并自报接触面 |
| 接触面自报 | 每个 PR 描述必须带一行：`接触面：T1 · n 个上游文件 / m 处改动 · slug=fork:<id> · audit leak 前 → 后` |
| 不引入第二个 agent loop | 所有“工具执行前拦截”走 pi 扩展 `tool_call` 事件 |
| 不引入第二套配置根 | 新数据进 `~/.pi/agent/` 或 localStorage，且 pi CLI 忽略后不报错 |
| i18n 三语同步 | 新增文案必须同时进 `lib/i18n/messages/{en,zh-CN,zh-TW}.ts`（`registry.test.mjs` 会卡） |
| 自带测试 | 新增 `lib/` 逻辑必须带 `.test.mjs`；纯 UI PR 至少一个源码断言测试 |
| 与 PROMA 计划去重 | 已在 `proma-pr-plan-2026-09-18.md` 排过队的项，只引用不重开（见 §5） |

## 2. FIX 族：六大重点问题的修法

### FIX-01 · 聊天 Markdown 流式路径节流与降级（P0）

- **目标**：让“中等长度 + 多代码块/公式”的消息在流式期间不再越打越卡。
- **依据**：`components/MarkdownBody.tsx:46` `useMemo(normalizeDisplayMath, [children])` 每个 delta 全量重跑；`lib/markdown.ts` 该函数约 385 行多遍正则；`MarkdownBody.tsx:112` 的 `components` memo 键含 `isStreaming`；`lib/markdown.ts:350-385` remark×3 + rehype×3（含同步 `rehypeKatex`）。对照 B：`ai-elements/message.tsx:532-534` 只有 `remarkGfm + remarkMath + rehypeKatex`，且插件数组是模块常量。
- **落点**：`components/MarkdownBody.tsx`、`lib/markdown.ts`
- **做法**：
  1. 流式期间对 `normalizeDisplayMath` 改用 rAF 节流（或只规范化新增尾部窗口），非流式再做一次全量；
  2. `components` 的 `useMemo` 去掉 `isStreaming`，把该标记只透传给 `CodeBlock` / `MermaidBlock` 两个叶子；
  3. 新增 `markdownStreamingRehypePlugins`（不含 `rehypeKatex`），流式结束后切回完整组。
- **接触面**：T1 · 2 个上游文件 / 3 处 · slug=`fork:fix-markdown-stream`
- **验证**：同一会话（~30KB 文本 + 4 代码块 + 10 公式）分别测首 token 到可读、流式帧率、结束顿耗时；三项均需下降；`tsc/lint/test` 过。
- **回滚**：单个 commit revert 即可回到旧行为。

### FIX-02 · 代码高亮：从“结束时一次性”改分片节流（P0）

- **目标**：消除“打字快、停下顿”的体感。
- **依据**：`components/MermaidBlock.tsx:264-287` `isStreaming || !highlighterReady` 时只渲染 `PlainCode`，结束后对攒下的大代码块一次性 Prism 全量 tokenize；`useLazyHighlighter.ts:1-14` 说明 Prism 全语言包 ~1.5MB 走 dynamic import。对照 B：`packages/ui/src/code-block/CodeBlock.tsx:180-226` 节流 80ms + 逐行 token + `markdown/LiveMarkdownPreview.tsx` 160 条 LRU。
- **落点**：`components/MermaidBlock.tsx`、`components/useLazyHighlighter.ts`
- **做法**：先做低风险版（不动依赖）：结束时按代码块分片 + `requestIdleCallback` 分帧上色，并加 `MAX_HIGHLIGHT_LINES` 上限 + 折叠；将“流式期渐进上色”列为可选后续（迁 Shiki）。
- **接触面**：T1 · 1 个上游文件 / 2 处 · slug=`fork:fix-highlight-chunk`
- **依赖**：FIX-01（否则节流被全量重解析掩盖）。
- **验证**：大代码块（>500 行）结束时的 main-thread long task 数量下降。

### FIX-03 · 长会话历史/实时隔离渲染（P1）

- **目标**：长会话不再因上翻而膨胀到全量重渲染；流式 token 只影响当前轮。
- **依据**：`lib/chat-lazy-load.ts:1` `VISIBLE_PAGE_SIZE=50`，但 `components/ChatWindow.tsx:838-844` 把 `visibleCount` 抬到 `messages.length`；`rendered[]` 每次 render 全量重建。对照 B：`agent/AgentMessages.tsx:735-795` 把稳定历史前缀与实时 tail 分开 memo。
- **落点**：`components/ChatWindow.tsx`
- **做法**：拆成“已完成历史（引用稳定）+ 当前流式 turn”两个 memo 列表；历史组在 token 更新时复用引用，使 `MessageView` 的 memo 生效。
- **接触面**：T1 · 1 个上游文件 / 2 处 · slug=`fork:fix-render-split`
- **验证**：500+ 消息会话中，流式一轮的 commit 数下降；上翻后帧率稳定。

### FIX-04 · 文件预览走轻插件组（P1）

### FIX-05 · 打包硬门禁（P0）

- **目标**：把“漏跑 `npm run build`、`.next/node_modules` 未注入、node-pty ABI/执行位、`files` 误排除”变成**构建期硬错误**。
- **依据**：`electron/main.js:392-395` 无 `.next` 就弹框退出；`scripts/after-pack.mjs:1-40` 把外部化依赖解引用拷进产物；`package.json` 的 `files` 排除串很长，靠人工核对。参考 Proma `sync-runtime-deps` 的“发现绝对 symlink 即硬失败”。
- **落点**：新增 `scripts/verify-desktop-bundle.mjs`（T0）+ `package.json` 加 1 行 script。
- **做法**：断言 `.next` 存在且非 dev 产物、`.next/node_modules` 包含 `node-pty/undici/pi-*`、`node_modules/node-pty` 有可执行位与正确 ABI、`files` 排除表未剔除必要项。失败即非 0 退出。
- **接触面**：T0 · 新文件 + 1 行 script · leak 不变
- **验证**：故意删 `.next/node_modules` 后门禁必须红。

### FIX-06 · dmg/zip target + afterPack + 三档冒烟清单（P0）

- **目标**：让 dmg/exe 真的能装、装完按钮能点。
- **依据**：`package.json build.mac.target: ["dir"]`（连 dmg 都不打）；`release/` 只有 `mac-arm64/*.app`；`electron/main.js:208-224` 的导航拦截会把非同一端口跳转静默吞掉；`proxy.ts:10-24` + `lib/file-access.ts:20-60` 的 allow-list 在包内可能因 homedir/userData 变化而把 `/api/files` 变 403。
- **落点**：`package.json` 的 `build` 段（T1，1 段）+ `scripts/` 下的冒烟脚本（T0）。
- **做法**：
  1. `mac.target: ["dir", "dmg", "zip"]`（zip 是以后自动更新的前提），`afterPack` 必须生效；nsis/deb 后置；
  2. 冒烟清单写成可执行脚本：开窗 → 发一句 → 回 → 文件树能列 → 终端 `echo` → 定时列表能拉 → 收集 `/api/files/*` 是否 403 与主进程 `will-navigate` 日志；
  3. 全仓 `localhost` 与 `127.0.0.1` 统一为后者；导航拦截加日志 + 前端 toast，不再静默。
- **接触面**：T1 · 1 个上游文件 / 1 段 · slug=`fork:fix-desktop-target`
- **依赖**：FIX-05。
- **验证**：三档产物都过冒烟；`release/builder-debug.yml` 的 `files` 逐项核对。

### FIX-08 · 文件树接上服务端 watch 订阅（P1）

### FIX-09 · 文件树 git status 防抖缓存 + 浅层列出（P1）

- **目标**：大仓不再每次刷新重拉 git status。
- **依据**：`components/FileExplorer.tsx:110-118` 的 `fetchGitStatus`，`useEffect 857-875` 每次 refresh 都重拉；`/api/git/status` 服务端已有 2.5s TTL（`lib/git-changes.ts:110-130`），前端未复用。
- **落点**：`components/FileExplorer.tsx`、`lib/git-changes.ts`（T1）
